6.1) Откат коммита по одному с конца
git revert af3d970					# см в заметках. Откатывает конкретный коммит af3d970(только один, это неудобно)
git push
6.2) Откат до нужной версии(мягко)
git revert --no-commit C2..HEAD				# отменить C3, C4, C5 разом, но пока не коммитить(C1 ─ C2 ─ C3 ─ C4 ─ C5)
git commit -m "Откат к состоянию C2"			# завершить одним коммитом (станет C1 ─ C2 ─ C3 ─ C4 ─ C5 ─ C6), где 6, как 2
							# --no-commit говорит «сложи все отмены вместе, не делай отдельный коммит на каждую».
git push
6.3) Откат жесткий до нужной версии
git reset --hard C2					# это вернёт ветку прямо к C2, а C3–C5 сотрёт (при C1 ─ C2 ─ C3 ─ C4 ─ C5)
git push --force					# из-за жесткого удаления push должен быть --force

7) Как переключиться на другую ветку
#Cоздаем ветку в GitHub в браузере скажем test_branch
git fetch						# узнать у GitHub: какие сейчас есть ветки (обновить список)
git switch test_branch					# теперь Git её знает → создаст локально и свяжет
							# все связи подтянутся автоматически и если надо будет запушить, то просто git push

Заметки:
2.1)origin — это просто короткое имя-псевдоним для длинного адреса GitHub
git remote add origin <url> = «запомни этот адрес под кличкой origin»

2.1)git branch -M main — что и когда?
  Переименовывает текущую ветку в main. Зачем: Git исторически создаёт первую ветку с именем master, а у GitHub стандарт
  — main. Чтобы имена совпадали, переименовываем. -M = переименовать принудительно. При клонировании это все делается

2.1)Что за -u в git push -u и чем отличается от git push без него?
  -u (= --set-upstream) при первой заливке запоминает связь между твоей локальной веткой и веткой на GitHub. Это
  делается один раз. Если бы ты не сделал -u, тебе пришлось бы каждый раз писать полную форму git push origin main

Только добавь привычку: на втором компе перед работой делай git pull (пункт 3.2) — чтобы забрать то, что залил с первого компа. Иначе версии разойдутся.

6)Откат коммита
  Разберём на твоём примере. Есть 3 коммита:
  C1 ── C2 ── C3
  - git revert C3 → появится C4, который отменяет только C3. Итог: C1 ─ C2 ─ C3 ─ C4, файлы как после C2.
  - Чтобы вернуть состояние к C1, надо отменить и C3, и C2:
  git revert C3
  git revert C2
  - Получится C1 ─ C2 ─ C3 ─ C4 ─ C5, а файлы станут как в C1.
